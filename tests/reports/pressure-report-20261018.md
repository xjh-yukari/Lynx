# Agent 异常恢复离线压力测试

测试日期：2026-10-18。使用当前 Windows 本地环境、假 Provider 与临时目录。
未调用真实模型或搜索 API，未修改 `.env` 或真实会话。

## 运行结果

3 倍负载：**7 passed in 39.84s**。

| 场景 | 负载与断言 | 结果 | 场景耗时 |

这些耗时使用立即返回的假模型，不能推断真实模型响应速度或公网并发吞吐。
内存是本场景开始后 tracemalloc 的 Python 分配峰值，不是进程 RSS，不是泄漏检测结论。

为触发回收与摘要，采用小窗口 8192、输入预算 6144、压力比例 0.65、正文回收阈值 2048 字符。
高摘要频率是负载设置所致，不代表默认配置。假摘要只测试流程，不评估实际摘要的语义保真。

## 发现及解释

首次 3 倍运行中，执行后保存故障测试失败：记录增长后自动摘要提前运行，注入的诊断保存故障发生在工具执行前，而测试误以为工具已经执行。随后假模型仍返回排队的工具调用，恢复器正确拒绝，并未执行新工具。

调整了测试注入条件，只在聊天阶段注入执行后诊断故障；另外新增“执行前维护故障”场景，验证两种阶段。未修改 Agent 核心代码来迁就压力测试。

当前 SessionStore 每次保存原子替换整个 JSONL 快照；源码确认不是增量追加文件。随着原始审计积累，磁盘、序列化和加载成本值得进一步分析。本次看到规模扩大时延迟和内存峰值上升，但未做独立性能剖析，不能断言某一种开销是唯一原因。

## 未覆盖的边界

- 真实 DeepSeek 的网络延迟、限流、推理预算和实际 Token 计数。
- 真实搜索服务稳定性、模型事实准确性及摘要是否保留关键约束。
- 同一个会话被多个进程同时写入：现有存储不支持，不能因本次多会话通过就认为支持。
- 恶意本地进程、断电、磁盘耗尽或进程强杀：这里是应用层故障注入，不等价于这些实机故障。
- 多用户身份隔离：本次只测试会话存档编号隔离，同一工作区的源文件仍按既有文件权限访问。
- 超长运行的内存泄漏与 GB 级会话存储性能。

## 复现

压力测试默认跳过，避免影响日常回归。PowerShell：

```powershell
cd E:\github\nanobot
$env:LYNX_PRESSURE_TEST = '1'
$env:LYNX_PRESSURE_SCALE = '3'
uv run pytest tests/stress/test_agent_pressure.py -q -s --durations=7
```

scale 支持 1–5，默认 1。运行后可关闭这个终端，或仅移除这两个临时变量：

```powershell
Remove-Item Env:LYNX_PRESSURE_TEST, Env:LYNX_PRESSURE_SCALE -ErrorAction SilentlyContinue
```

删除的是当前进程环境变量，不是文件，也不修改 `.env`。
