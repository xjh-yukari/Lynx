# Lynx 训练工程助手需求文档

文档版本：0.3。日期：2026-10-27。已纳入用户补充决策、只读环境探测、完整工具需求与验收门禁。

实施状态：需求讨论稿，尚未实现；不属于 V1.0.0 已交付功能。本文用于确认范围，不构成启动训练、租用 GPU、连接服务器或修改训练代码的授权。

## 1. 目标与定位

在现有 Lynx Agent 上增加训练工程辅助能力，帮助用户记录、校验、调度、观察和评测后训练实验，并在失败时提供可核对的诊断与修改建议。目标是减少重复操作和实验信息丢失，不是提出论文研究点，也不开发新的训练算法。

用户负责实验目标、数据划分、评价指标、验收要求和资源预算；Agent 负责解释、工具调度与建议；程序负责真实状态采集、权限校验和持久化。模型判断不作为任务成功的唯一依据。

当前产品与权限边界以 [产品方案](product-plan.md) 为准；本模块不得绕过现有审批、文件保护、MCP 和知识库授权。

### 1.1 已确认决策

| 决策 | 内容 |
| --- | --- |
| C01 执行环境 | Windows + WSL 协作，当前训练在 WSL 内执行；首版不接 SSH 服务器或集群 |
| C02 实验场景 | GRPO / SFT 对照实验；用户原文“stf”暂按 SFT 理解，若非此意须纠正 |
| C03 首版闭环 | 用户提需求 → 需求设计 → 写代码 → 测试 → 提交训练与评测 → 历史对比 → 分析和记录 |
| C04 自主权 | 用户决定需求，Agent 在授权范围内改代码并验证；不是只读建议模式，也不是自主改变实验目标 |
| C05 数据流 | 任务相关代码、日志与必要资料可以发给 DeepSeek，生成代码保存本地；暂不设置额外禁止外发的数据分类，凭据保护继续生效 |
| C06 数据职责 | 实验结构化数据用本地 SQLite；长期记忆继续通过 MCP 接入 Engram，不迁移或替换现有记忆系统 |
| C07 资源与时长 | 以本人电脑实际配置为资源边界，不租用或扩容；支持无固定运行时限，直到任务完成、失败或用户请求暂停/停止 |
| C08 版本追踪 | 使用 Git commit 保存代码版本并提供回滚机制；实验记录关联代码版本、配置、数据与产物 |
| C09 自动接入 | 用户只需提供源码位置和任务目标；Agent 负责环境探测、框架识别、命令分析、路径规划和授权范围内的迭代，不要求用户手工整理启动命令 |
| C10 暂停方式 | 已确认保存检查点后退出，之后从检查点继续训练；不使用挂起进程冒充可恢复暂停 |

上述为需求决策，不代表功能已实现。当前源码位置尚未提供，不能宣称已识别实际训练框架；应由项目探测工具在获得路径后完成，而不是让用户先回答所有技术细节。

## 2. 典型使用流程

1. 用户登记 WSL 训练项目，提出 GRPO/SFT 对照目标、允许修改范围与验收要求。
2. Agent 梳理需求、基线和实施计划；关键不明确项由用户确认，不自行改定评价指标。
3. Agent 在获批范围内编写或修改代码、补充测试；在隔离工作目录中验证，不修改正在运行任务的代码快照。
4. 测试通过后创建 Git commit，记录需求版本和变更；检查配置、输入、资源及输出冲突，形成待批准任务快照。
5. 批准的流程可包含训练结束后的评测；调度器在 WSL 内提交任务并返回持久 job_id，不因模型调用超时杀死训练。
6. 程序采集真实状态与日志；Agent 按需解释。关闭 TUI、切换会话或模型断连不取消任务。
7. 完成训练后执行批准的评测，登记指标与检查点，对比选定历史基线，写入 SQLite 并生成分析报告。
8. 用户可请求暂停、恢复或停止；异常保留证据与建议，修复后的代码、新配置和重跑形成新版本及关联任务。

示例需求：“为这轮 GRPO 与 SFT 对照实验完成实现和测试，提交代码；按确认的两套配置运行，结束后执行共同评测，与指定历史基线比较并记录。不要自行更换数据划分或评价指标。”这是流程示例，不构成当前执行授权。

## 3. 首版范围（依据补充决策更新）

| 编号 | 功能 | 要求 |
| --- | --- | --- |
| F01 | 项目与实验登记 | 登记项目、目的、输入和代码版本；不绑定单个聊天会话，跨会话可查询 |
| F02 | 训练前检查 | 检查配置结构、必填字段、输入存在性、输出冲突及可用资源；未知项标明未验证 |
| F03 | 任务提交 | 从用户配置的入口提交已批准任务；默认并发为 1，不自动租赁或扩容 |
| F04 | 状态与日志 | 查询真实任务状态、退出码、时间及分段日志，记录采集时间与数据来源 |
| F05 | 持久运行 | 关闭 TUI、切换 Session 或模型断连不终止已提交任务；重启可重新关联 |
| F06 | 指标与产物登记 | 对支持的日志格式确定性提取指标，登记检查点路径；未知格式保留原文，不臆造指标 |
| F07 | 评测与对比 | 执行用户批准的评测入口；对齐指标定义、数据版本和运行设置，标明不可直接比较的项目 |
| F08 | 暂停与停止 | 按指定 job_id 请求暂停、恢复或停止，分别核实真实结果；语义见第 6 节 |
| F09 | 异常诊断 | 展示证据、候选原因和建议；用户提出修复需求后可改代码和测试，不自行改变目标或无限重试 |
| F10 | 结果导出 | 导出结构化记录与 Markdown 报告，可回查原始指标与日志；排除凭据与未授权数据 |
| F11 | 需求与代码实现 | 保存需求版本、批准范围与验收项；Agent 按用户需求实现代码，展示差异并执行相关测试 |
| F12 | Git 版本与回滚 | 测试通过后创建 commit，实验绑定确切版本；回滚前检查依赖和未提交内容，保留历史 |

首版只实现本机 WSL 执行后端，但需接入用户现有 GRPO 与 SFT 两条训练入口和评测入口；二者不要求使用同一框架。Windows 侧复用现有 Agent 交互与控制能力；WSL 内负责训练进程、环境、日志和检查点。Agent 根据源码、配置与现有环境识别入口及框架能力，不能只因项目名含有 GRPO 就声称适配完成。

### 3.1 对照与历史分析

对照组共享明确的 experiment_group_id，各任务保留各自方法、模型/检查点、配置与训练指标。用户指定比较基线；程序核对评测任务、数据划分、指标定义和预算条件，列明差异。不能把 GRPO 的 reward 与 SFT 的 loss 直接当同一个指标比较，应以用户确认的共同评测为主要依据，同时单独报告耗时、资源和训练曲线。

支持显式登记已有历史实验：可获取的原始日志和指标保留引用，缺失的 commit、配置或数据版本标为未知，不补造历史。历史不完整的比较应降低结论强度，不能宣称严格受控实验。

## 4. 自主执行与审批边界

| 操作 | 建议边界 |
| --- | --- |
| 查询已授权任务、读日志、记录事实 | 自动，只读或限定记录目录写入 |
| 生成配置和诊断建议 | 自动提出候选，不替用户确定实验目标 |
| 启动训练、评测 | 每个任务绑定准确批准；可在一次批准中明确列出训练及后续评测，不授予未限定任务的空白授权 |
| 停止任务 | 用户指定目标并批准；不根据日志内容自行杀进程 |
| 按用户需求修改训练代码 | 首版支持，在授权项目和范围内实现、展示差异、配套测试并 commit；仍遵守现有文件审批 |
| 调整超参数、修复后重跑 | 按用户要求或批准方案执行，形成新配置与任务；不自行扩展搜索范围 |
| 修改数据划分、指标、验收阈值、删除测试断言 | 必须单独由用户确认，不能作为自动修复手段 |
| 安装环境、删数据或检查点、租赁或扩容 GPU | 不在首版自动执行范围 |

批准应绑定程序、参数、目录、输入版本、输出位置、资源与限制。关键内容发生变化，旧批准失效。密钥仅引用受保护配置，不写入批准快照、命令行展示或报告。

模型可以执行验证，不能自行降低验证标准。训练项目同样要求每次独立改动配套测试、验证通过后创建 Git commit。既有关键测试、评价指标和验收标准的修改需要单独确认，不能仅凭“所有测试通过”宣布实验科学结论成立。获批执行程序不等于获得操作系统沙箱，不能扩大宣称现有隔离能力。

## 5. 实验记录与数据职责

每个实验必须有 experiment_id；每次提交有独立 job_id 和 attempt_id。重试或恢复检查点需记录与原任务的关系，不覆盖原失败记录。

最低记录集合：实验目的与需求版本；experiment_group_id 和基线关系；训练方法；训练代码 commit 和工作区状态；模型标识与可获得的 revision；数据标识、划分与可获得的版本；实际解析配置；随机种子；训练和评测入口；Windows/WSL 发行版及环境信息；请求与实际分配资源；任务时间、状态和退出码；指标、日志和产物引用；授权记录；暂停/恢复记录；关联任务。

无法取得的数据版本或环境信息必须标为未知。新建训练任务建议只使用测试通过且已提交的代码快照；存在影响执行的未提交或未跟踪文件时拦截并说明，不自动丢弃用户修改。记录 commit 仍需保存实际解析配置、启动环境和外部依赖，不能据此承诺完全复现。

- 实验记录存储：已确认采用本地 SQLite，保存项目、需求版本、实验组、任务、事件、指标与产物引用；不替换 Engram。
- 日志与产物：独立目录，保留路径、完整性信息和必要副本；不把大模型权重塞进数据库、Git 或模型上下文。
- Session：用户对话与操作说明，删除或清空上下文不删除实验。
- Engram：继续通过 MCP 访问，可保存带 experiment_id、版本与来源的经验结论，不作为原始指标与任务状态的权威来源。SQLite 写入成功不等于 Engram 必须同步成功，记忆连接失败不阻塞训练与台账保存。
- RAG：查询训练资料、论文和项目说明，不代替结构化实验台账；不得未经批准自动导入数据集或日志。

实验数据目录独立于源码；默认根目录见第 10 节，由 Agent 规划而非要求用户手工指定。容量和保留策略应依据实测资源生成计划；首版不自动清理产物。不能承诺仅凭记录就实现数值完全复现。

SQLite 由 WSL 内管理服务负责写入，存储与访问方案见第 10、12 节；Windows 不直接并发写同一共享数据库。日志与检查点保留各自系统路径和主机/发行版标识，不把 Windows 路径未经映射直接交给 WSL。

## 6. 执行架构与接口建议

TUI/Agent → 训练工具层 → 实验管理器与审批 → 后端适配器 → 已有训练/评测程序。

训练继续由已有框架执行；新增模块不实现梯度计算。训练进程不能作为普通工具调用一直等待到结束，提交工具应快速返回 job_id；WSL 后端负责长期运行与持久任务关联，不能依附于 TUI 的可取消工具进程树。连接和停止只能作用于显式授权的发行版与任务；首版不增加远程主机权限。

拟提供 inspect_resources、validate_training、submit_training、get_training_status、read_training_logs、run_evaluation、compare_experiments、request_pause、resume_training、request_cancel，以及复用现有文件、测试与受控 Git 执行能力。名字、参数与文件布局是设计建议，不是当前已注册工具；不急于新加 MCP 服务、FastAPI、Redis 或网页前端。

状态至少区分：待批准、排队、启动中、运行中、暂停中、已暂停、恢复中、取消中、成功、失败、已取消、状态未知。重启或连接中断后先核实真实状态；不能把失联判成失败、重复提交，或把日志末尾的“完成”文字当成成功信号。

提交须具备幂等键；请求超时或回应丢失后可查询原任务，不能直接再次启动。退出码为 0 仅说明进程正常退出，产物和评测还需独立验证；训练成功与评测通过必须分别表示。

### 6.1 无固定时限与暂停语义

用户可以选择无固定时限，不设置统一的墙钟超时来强杀正常训练；训练自身结束仍应正常结束，不自动发起下一轮。状态查询、日志读取等短请求仍有超时与取消边界。资源不足、磁盘不足或硬件故障需要报告并按批准规则处理，不能承诺电脑永远在线。

暂停采用已确认的“保存检查点并有序退出，之后继续训练”。请求需被训练适配器接收，在可恢复的安全边界保存并确认完成后退出；不能把普通 SIGTERM、挂起进程或仅停止显示视为成功。恢复前检查模型/适配器权重、优化器、调度器、随机数、训练步与框架所需数据进度，区分完整续训与只加载权重重启。GRPO 适配还需核实采样、rollout 与奖励相关状态的恢复边界，不能默认与 SFT 相同。

检查点由临时目录完成写入与验证后发布可恢复标识，半成品不可选作恢复入口。写盘失败、空间不足、超时、用户取消或框架不支持时，不报告已暂停，不删除上一有效检查点，不自动强杀；向用户提供继续等待或批准停止的选择。安全边界等待时间与失败策略记入项目能力清单。

停止、暂停和恢复是不同操作。关闭 Windows、休眠或执行 WSL shutdown 不属于关闭 TUI，不能保证训练继续；需要单独说明检查点策略和故障恢复能力。

### 6.2 Git 保存与代码回滚

每次独立的需求实现或修复通过测试后创建 commit，记录需求版本与测试结果。训练任务使用固定代码快照，后续修改不能改变正在运行任务的代码。回滚由用户指定目标、预览差异并批准，优先用新增 revert 提交或隔离的历史版本工作目录，不能默认 reset --hard、删除未跟踪文件或改写历史。

回滚后重新运行相关测试，记录新 commit 与所针对版本；代码回滚不自动回滚 SQLite、数据集、模型权重或已经发生的训练。检查点恢复是独立操作，必须核对代码、模型、数据和环境兼容性。首版不把新功能代码写进已经发布的 V1.0.0 标签，也不移动既有标签。

## 7. 故障、安全与成本要求

- 所有执行、状态变化和人工批准可追溯，日志与报告做已知密钥脱敏；不承诺完全检测所有敏感信息。
- 模型断连不影响任务；后端失联显示未知并允许恢复关联；硬件故障不承诺自动恢复。
- 首版不自动重试。后续只对明确分类的临时故障按用户批准的次数重试，写操作与检查点续训不可盲目重做。
- 不在正在运行的任务目录修改代码或配置。受控实现和修复使用隔离工作目录，新代码对应新实验快照。
- 资源以用户电脑实际 GPU/显存、内存和磁盘为边界；首版默认串行队列、不自动租用或扩容。具体配置采集后设置资源检查；无固定运行时限不等于无资源限制，也不意味着自动无限重试。
- 用户允许为任务向 DeepSeek 发送必要代码、日志和资料，返回代码保存在本地；这仍包含向外部 API 发送输入，不是全本地推理。暂不增加额外禁止外发的数据分类，但密钥、令牌和受保护凭据仍需排除，不能提交 Git、写入报告或随意发给模型。
- 不自动扫描全盘或无关目录；按任务需要选取有界片段，控制上下文与费用。日志与资料内容不构成新增授权。将来新增禁止外发规则时，程序应能校验并执行。

## 8. 验收案例（规划，尚未执行）

| 案例 | 预期结果 |
| --- | --- |
| 输入不存在、配置缺字段、输出冲突 | 提交前拦截，未启动进程，原因明确 |
| 未批准或批准后更改参数 | 不执行；要求新批准 |
| 提交回应丢失、重复提交同一请求 | 查询并关联同一任务，不重复启动 |
| 训练中关闭 Agent，再重新打开 | 可查询同一 job_id；关闭界面不取消训练 |
| Windows 入口控制 WSL 训练 | 使用指定发行版、Linux 环境与映射后路径，执行结果可追溯 |
| 无固定时限任务超过普通工具超时 | 训练继续，仍能查询、暂停和停止；不因此启动重复任务 |
| 请求暂停并随后恢复 | 根据框架能力保存并核实检查点，恢复与旧任务关联；不支持时明确说明 |
| 远程断连或状态采集失败 | 显示未知和最后采集时间，不伪造成功/失败 |
| 程序正常退出但缺少约定产物 | 保留退出码，标记验收未通过，不宣布实验成功 |
| 训练成功、评测失败 | 两个状态独立保留，报告失败依据 |
| 请求取消任务 A | 仅影响 A，确认实际退出；不误杀任务 B |
| 日志含密钥或要求改变权限的文本 | 不向模型和报告泄露已知密钥，不执行日志中的指令 |
| 对比不同数据版本或指标定义 | 标明差异，不直接输出“某方案更好”的结论 |
| 对比 GRPO 与 SFT | 使用确认的共同评测，训练 reward/loss 分开展示，记录历史基线版本 |
| SQLite 保存成功但 Engram 不可用 | 台账仍可查询，不回滚已完成训练，不伪造记忆写入成功 |
| 按用户需求修改代码并测试 | 保留差异、相关测试、固定验收项和 commit，实际执行对应快照 |
| 用户请求回滚代码 | 不覆盖未提交修改，不删除实验记录或检查点，回滚后验证并记录版本 |
| 建议修改验收脚本以消除错误 | 不自动修改，要求用户单独确认 |
| 不启用训练模块 | 现有对话、会话、工具、记忆、RAG 功能保持不变 |

自动测试先用临时数据和假训练进程覆盖生命周期，不消耗 GPU。实际后端确认后，增加授权的小规模真实训练与评测验收；不能以替身测试通过代替真实环境验收。现有测试与副作用说明见 [测试入口](../tests/README.md)。

## 12. 模块、接口与持久状态契约

建议在主包增加 training/ 域：models、policy/approval、discovery、planner、workspace、git、registry、service/client、scheduler、artifacts、metrics、reports、adapters。WSL worker 的运行环境与训练项目的环境分离，不能把 Torch 等重依赖装进 Windows Agent 根环境。具体包拆分在实现前设计，不在本轮创建占位源码。

优先使用 WSL 用户级 systemd 托管 worker 与每个训练任务，任务按 unit/进程组识别并分开于 TUI；安装、启用与更改服务需要明确批准，不需要默认 root。用户级管理不可用时应阻止正式提交并报告缺项，不能悄悄回退为依附 TUI 的子进程。systemd 不是 WSL 永久保活或宿主机断电保障，必须实测关闭终端后任务持续性；系统退出只能依赖已验证的 checkpoint 恢复。[Microsoft WSL systemd 说明](https://learn.microsoft.com/en-us/windows/wsl/systemd)。

Windows 客户端通过明确发行版的 wsl.exe --exec 调用受控 worker 客户端，使用有版本的 JSON 请求/响应；后台任务由服务执行而非这个短命令执行。首版不暴露公网端口；控制入口限制本地用户，不能声称能防御同一系统账户下的其他恶意进程。请求允许的方法和路径按项目权限校验，密钥不在 argv/JSON 日志里传输。

共同请求包含 api_version、request_id、project_id、operation、参数、plan_digest 和必要的 approval_id；响应包含 status、job_id/attempt_id、observed_at、结构化 data 或 error_code/retryable/evidence_ref。未知字段和方法拒绝；参数变化会使 plan_digest 与原批准失配。代码 commit、环境标识与配置摘要均属于计划。暂停/取消需请求幂等；不能因重复消息作用到别的任务。

SQLite 数据实体至少包含 projects、requirements、plans、approvals、code_versions、experiment_groups、experiments、jobs、attempts、job_events、metrics、artifacts、checkpoints、reports、schema_versions。唯一 request_id 和必要约束防重复提交；事务保存计划与派发意图，worker 启动/状态回填之间崩溃时由协调器按任务 unit、进程启动身份和幂等键对账，不能只凭 PID（可能复用）判定归属。

事件追加并保留时间与来源；状态转换必须合法，迟到的运行心跳不能覆盖已核实的终态。指标保留名称、单位、step、split、评测协议版本和证据位置，模型推断与原始指标分字段存放。API 序列化拒绝 NaN/Inf 伪装为正常数值，原始异常可留证据。每次迁移前一致性备份，迁移失败不发布新 schema；代码回滚发现不兼容 schema 时只读或阻止启动，不能盲目覆盖数据库恢复现场。

容量与轮询初始策略：GPU 密集训练/评测合计并发为 1；默认 10 秒一次状态观测、无变化退避到 60 秒，不每次调用模型；单次日志返回最多 16,000 字符并支持后续游标；日志存储按段轮转并记录是否截断，不默认承诺无限完整保存。周期可配置，实际 GPU/内存/磁盘余量提交前重测；WSL 可扩展磁盘的来宾空间不能替代宿主磁盘检查。低空间时停止接收新任务，运行任务先报告并按 checkpoint 策略处理，不删旧产物腾空间。

## 13. 实施门禁与新增验收

### 13.1 分阶段完成标准

- G1 接入：给定源码位置即可产生带证据的环境/框架能力清单；不要求用户手工给命令；不执行未知脚本。
- G2 代码闭环：需求版本、修改范围、保护的验收项、测试和 commit 相互关联；有界迭代失败停止，不修改通过标准。
- G3 台账与持久调度：SQLite 迁移、备份、唯一提交、重启对账、现有任务只读观察通过替身/故障测试。
- G4 框架适配：实际 GRPO 和 SFT 入口分别完成授权的小规模训练、共同评测、checkpoint 暂停与续训。只有权重加载不算完整续训。
- G5 端到端：Windows → WSL → 固定代码 → 训练/评测 → 历史对比 → 报告；关闭 TUI 后仍运行，代码回滚不破坏历史产物；明确尚未验证的条件。

所有阶段都必须更新测试、验证通过再 commit。真实 GPU 验收需有任务授权，在隔离数据/目录进行；不为验证暂停功能操作用户当前运行中的实验。首版发布需两条实际入口均通过，不能只凭通用假训练器宣布“支持 GRPO/SFT”。

### 13.2 必须覆盖的故障与边界

| 测试编号 | 场景 | 验收要求 |
| --- | --- | --- |
| A01 | 源码路径包含空格、Unicode、越界链接或错误发行版 | 正确定位或明确拒绝，不误操作其他项目 |
| A02 | 入口脚本在导入/--help 时执行训练 | 静态发现不执行；实际探针需要批准和副作用边界 |

| A06 | SQLite 锁冲突、损坏、迁移失败、活跃备份恢复 | 不丢状态、不重复提交，限制写入并报告；恢复在隔离副本验证 |

| A10 | DeepSeek 超时、SQLite 正常但 Engram 断开 | 训练和台账继续，解释或记忆延迟明确展示 |
| A11 | 未批准的命令、安装、指标修改或凭据提交 | 程序侧拒绝并留审计；模型文字不能批准自己 |

文档回归只验证需求索引、链接和状态标记，不等于上述功能测试。自动测试使用假的服务与训练进程；WSL 冒烟使用临时项目；真实 GPU 测试显式开启并清楚报告 skip。资料参考仅为实现依据，不替代锁定实际框架版本和真实验证。[Transformers checkpoint/恢复说明](https://huggingface.co/docs/transformers/trainer_recipes)说明恢复还涉及优化器、调度器与随机数状态，因此不能把只存权重当作完整暂停恢复。
