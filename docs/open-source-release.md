## 发布门禁

- [x] 维护者确认采用 Apache-2.0，已添加 LICENSE / NOTICE 并同步 README / 包元数据。
- [ ] 核对第三方代码/图像的来源及分发要求，参见 [第三方说明](../THIRD_PARTY_NOTICES.md)。
- [ ] 接受或处理 Git 提交者姓名、邮箱、历史本机路径以及报告/图片可能包含的个人信息。它们不等于 API 密钥，但公开历史会暴露这些内容。
- [ ] 检查下面命令的结果及扫描范围，不能只看当前 `.gitignore`。
- [ ] 运行完整测试与 Ruff，明确跳过及未验收部分。
- [ ] 在独立检出目录按 README 验证基础安装。重型 RAG/WSL 组件另外验收，不宣称跨平台已全部通过。
- [ ] GitHub 仓库创建后启用可用的秘密扫描、推送保护及私密漏洞报告功能；不把这些功能视为完整审计替代品。
- [ ] 只推送人工确认的分支/标签，不盲目使用 `git push --mirror`。标签仍可能指向旧文件。

## 本地只读检查

```powershell
uv run --locked python scripts/check_publication.py --history
git status --short
git diff --cached --stat
```

脚本扫描 Git 索引对应 blob、已跟踪工作文件，以及 `--history` 指定的所有本地分支/标签可达对象；还会检测可能误纳入的本机配置、私钥及数据库文件。读取本地 `.env` / `config.toml` 和敏感名称的环境变量仅用于精确匹配，不回显值。额外密钥文件可通过 `--secret-file <文件路径>` 加入匹配，**不要把密钥本身写进命令参数**。

扫描输出只含位置、对象编号和规则名称，不含命中正文。超出大小限制或检查失败会阻止通过。已知合成测试占位符仅作精确值豁免，不按整个 tests 目录放行。脚本不扫描未跟踪文件、不识别所有未知凭据、不进行图像OCR、不覆盖Git LFS远端对象或外部服务副本；新文件加入索引后必须重跑，截图和历史报告需人工检查。

若发现真实密钥，先撤销/轮换，再决定如何处理历史。历史改写、删除标签或创建全新公开历史均需维护者单独确认，不能通过“只删当前文件”代替。
